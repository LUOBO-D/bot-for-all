## 4. S3 M3 调度层（8–10 人日）

> 目标：让大肥鱼"活着"——有作息、会主动说话、睡觉时整理记忆、能联网。

| 编号 | 任务 | 涉及模块 | 验收标准 | 预估 |
|---|---|---|---|---|
| S3-01 | **作息状态机**：`active/drowsy/asleep` 三态，按 `schedule_json` 切换；`asleep` 不主动发言，@ 提及有概率"被吵醒式回复"；状态注入 prompt | `services/schedule.ts`（新增） | 改系统时间可观察到三态切换；`asleep` 下主动任务被拒 | 1 天 |
| S3-02 | **主动发言调度**：按房间唤醒 → 读近 50 条 → 轻量 LLM 判定 `{speak, message, reason}`；硬约束：每房每小时 ≤2、bot 总帽 6、cool_down 30min、冷场不发 | `services/proactive.ts`（新增） | 连跑 24h 模拟：无超频、冷场零消息、被拒时无副作用 | 2 天 |
| S3-03 | **`BotJob.trigger` 改可选**：让主动发言与非消息型任务进同一队列；队列按 `(room,bot)` 串行 | `bot/queue.ts`、`bot/gateway.ts` | 主动任务与 @ 回复不交叉；并发测试通过 | 0.5 天 |
| S3-04 | **companion speak 决策门**：`all` 模式在去抖后先判定要不要回；`mention` 保持必回 | `bot/trigger.ts`、`bot/gateway.ts` | 活跃房间下机器人回复率显著低于消息数（可配置） | 1 天 |
| S3-05 | **睡眠整理 Job**：02:00 起按房间批处理，提取梗/事件/印象与好感度、生成日摘要、衰减合并、写 `bot_memory_log`；只读区块哈希校验 | `jobs/consolidate.ts`（新增） | 跑一遍后梗库可检索到当日新梗；重复执行幂等 | 2 天 |
| S3-06 | **SearXNG 接入**：内网容器 + JSON API 调用（5s 超时、Top 5、失败降级为空）；`web_search` 工具落地 | `bot/tools/search.ts`、`docker-compose.dev.yml` | 搜索未启动时不影响回复；有结果时引用合理 | 1 天 |
| S3-07 | **时间与延迟策略**：快速路径（@/问号/含 bot 名）防抖 1s、无延迟；闲聊 1–3s 延迟 + 分段发送（各占 seq） | `bot/gateway.ts`、前端渲染 | 实测首字延迟 < 1.5s（快速路径）；分段显示正常 | 1 天 |
| S3-08 | **成本闸门**：主动判定用轻量调用（max_tokens 200）；整理批处理；记忆条目上限 5000 + 超限强制衰减 | `config.ts`、`services/memory.ts` | 24h 模拟下调用次数可预测、无失控增长 | 0.5 天 |

**DoD**：连续 3 天"养鱼"验收：会用当日梗说话；半夜 @ 会"被吵醒"；主动发言不超频；问"昨天群里聊了什么"能答对；角色卡自改留痕可回滚。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| M3 上下文膨胀导致成本/延迟失控 | 回复变慢、账单飙升 | S2-03 装配器限制各 provider 预算；S3-08 成本闸门；上下文条数与字符上限保持可配 |
| 主动发言变成骚扰 | 用户反感、被房主关掉 | 硬约束优先于模型自觉（S3-02）；上线前用模拟 24h 压测 |
| 记忆检索命中率低 | "记得住"体验不成立 | 关键词强制由写入方生成；先用真实群聊语料回归，再考虑向量检索 |
| 角色卡自更新导致人格漂移 | 机器人"变了一个人" | 只读区块 + 单次幅度 ≤10% + 每日 ≤2 次 + 睡眠期哈希校验自动回滚 |
| 自签 CA 在 iOS 上体验差 | iPhone 用户打不开 | S4-05 优先 PWA + 明确引导；必要时为 iOS 单独买域名（仅 iOS 走域名） |
| 单人开发节奏中断 | 阶段半途而废 | 每阶段独立可验收，S1 结束即可上线"内部可用版" |
