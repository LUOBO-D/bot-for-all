# UI 深度打磨规格书（v2 · 2026-11-01）

> 把现有四个页面与全部交互组件做到 Awwwards / Webby / FWA 获奖级品质。
> **加深，不加宽**：不新增页面、不新增功能、不改后端与数据流，只把已有的东西做到极致。

## 一、品质红线（不满足即视为未完成）

1. WCAG 2.2 AA：正文对比度 ≥4.5:1，大字 ≥3:1；全流程键盘可达；焦点可见且不被裁切。
2. Lighthouse 性能/可访问性/最佳实践 ≥90；CLS < 0.05；交互响应 < 150ms。
3. 动效只用 transform/opacity，稳定 60fps；`prefers-reduced-motion` 下全部可关闭。
4. 触控目标 ≥44×44px；移动端无横向溢出、无软键盘遮挡、适配安全区。
5. 空/加载/错误/离线/流式/长列表六类状态全部有专门设计。

## 二、原创性要求

1. 以"深海声纳"为唯一视觉母题：消息是声纹、机器人是发光鲸、面板是海沟切面；禁止把玻璃拟态+渐变+圆角当设计本身。
2. 至少一处签名式交互（消息声纹涟漪 / 机器人回复时的生物荧光呼吸），不影响性能与可读性。
3. 文案使用产品自己的语言，不出现通用系统腔。

## 三、工作项

1. 建立完整设计令牌：主色 ≤3 + 中性阶、字阶比例、4px 间距基线、圆角阴影层级、三档动效曲线。
2. 重做登录/注册/房间/聊天四页的信息层级与留白，消灭"为填满而填满"的装饰。
3. 双密度模式：舒适（大学生）/紧凑（科研），同一套组件自动切换行高与字号。
4. 聊天区专项：长消息折叠、代码块排版与复制、@提及高亮、流式呼吸态、未读分隔、消息分组与引用。
5. 机器人回复态：生成中/完成/失败三态视觉区分，失败可重试，不吞错误。
6. 全组件状态补全：空、加载、错误、离线、无结果、权限不足。
7. 响应式：桌面宽屏、笔记本、平板、手机四档断点逐一验收，含横屏与软键盘。
8. 动效规范落地：入场/反馈/转场三档，逐项写明触发、时长、曲线、降级策略。
9. 建立视觉回归基线：四页 × 三断点截图（本地，不入主分支）。
10. 自我迭代：按"排版留白 → 视觉层级 → 色彩 → 动效 → 微交互 → 响应式 → 原创性"七维逐项打分，任何一项 ≤8/10 继续改。

## 四、验收证据

- WCAG AA 对比度与键盘测试记录
- Lighthouse 四项分数截图
- 视觉回归对比结果
- 四页 × 三断点截图
- 七维自评表与迭代记录

## 五、非目标

- 不新增页面、不新增功能、不改后端、不改数据结构与接口
- 不引入新的重型框架
- 不堆叠装饰性特效、不做影响阅读的炫技动效
- 不引用外部字体/图片 CDN（纯 IP 离线环境必须可用）

## 六、交付物

1. 可运行的前端改造（保持现有数据流与测试选择器不变）
2. `docs/design-tokens.md`（设计令牌与使用规范）
3. `docs/ui-quality-report.md`（七维自评 + 外部标准验证结果）
4. 视觉回归基线截图（本地，不入主分支）

## 七、执行顺序

建令牌与基线 → 四页重构 → 状态补全 → 动效规范 → 七维自检迭代。
